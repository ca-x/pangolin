# Parity review — system settings and background work

Scope: the System settings page (scope tabs, appearance/branding, orchestration document, storage
targets, backup/restore, webhooks, jobs, retention, request-logging policy, about), the durable
job/scheduler machinery behind it, and the console surface for catalog subscriptions (which lives
on the Models page).

Method: re-derived from Pangolin's own code (paths relative to the repository root) and from
AxonHub's console/Go packages (paths relative to `/home/czyt/code/others/axonhub`), read as a
behaviour reference only. No code or assets were copied. No build, test or lint command was
executed. Several files in the working tree are modified but uncommitted, and
`src/api/operations_api.rs` was being written by another workstream while this review was read
(mtime 17:56), so its line numbers are as of 2026-09-21 17:57.

Status legend:

- `parity` — the operator-visible behaviour matches (the row notes where Pangolin goes further).
- `gap` — the experience is missing or wrong in Pangolin's console although the data or route exists.
- `feature-build` — the capability does not exist in Pangolin at all.
- `refuted` — the difference was claimed but does not hold.

## Notes

- Dead schema: `backup_configs` (`src/db/schema.rs:601-612`, `src/operations/schema.sql:58`) is created
  and migrated but no Rust code reads or writes it. The console's backup-schedule editor writes
  `operation_schedules` instead, so `backup_configs.retention_count`, `conflict_strategy`,
  `resources_json` and `schedule` are unreachable. Row 14 covers the operator-visible half of this.
- The request-logging policy is the only JSON document in this area without a `version` field, while
  its neighbours all declare one: `retry_statuses_json`, `conditions_json` and `schedule_json` default
  to `{"version":1,...}` (`src/db/schema.rs:349`, `:361`, `:378`) and the webhook envelopes are
  written as `{"version":1,...}` (`src/api/operations_api.rs:1296`). That is why row 11 is worth
  fixing rather than documenting as a convention.
- Nothing in this review was executed. Rows 1–9 assert that the capability exists as described, not
  that its current test suite passes.
