## Claims checked

- "The console used to render invented zeros instead of `—`" — **refuted for the current tree**.
  Every Overview stat is gated on `measured` and prints `—`, and the projection-down case raises
  a persistent alert (`web/src/observability.tsx:10,54-98`; `web/src/pages/OverviewPage.tsx:46-51`).
  A measured zero still prints as `0`/`$0.000000` by design (`observabilityTruth.test.tsx:80-87`).
  What remains true is the narrower row 4: the *failure reason* is unrendered in the list.
- "Request rows used to flatten every upstream failure to 502" — **still true for the status code**
  (`src/operations/lifecycle.rs:582`), so the status column and its facet can only ever be
  `200` or `502`. The reason now exists as `error_kind` (row 4) and is rendered only on the
  detail page (`web/src/pages/OperationsPage.tsx:278-283`).
- "The request list now carries `error_kind`" — **true at the API, false at the console**:
  returned by `src/observability.rs:76/662/691`, absent from `web/src/api.ts:18` and from the
  rendered columns.
- "The filter accepts `from`/`until`" — **true at the API** (`src/observability.rs:90-93`),
  **never sent by the console** (`web/src/pages/OperationsPage.tsx:61-65`); the generic
  resource lists ignore the parameters altogether (row 2).
- "A trace can now be opened by the client-supplied trace id" — **true** (row 16), with the
  `LIKE`-search caveat.
